# Telegram Aggregator

Собирает публикации из общей папки Telegram и пересылает их в темы твоей приватной группы. Ты выбираешь, какие каналы читать и в какие темы их направлять. Агрегатор отсекает точные дубли, распознаёт рекламу по явным признакам и умеет отбирать посты по реакциям. Классификация и фильтрация работают локально по правилам.

Один экземпляр обслуживает одну папку и один форум. Пользовательский аккаунт читает источники и пересылает посты. Отдельный бот опционален и нужен для кнопок управления. Если хочешь видеть пересылки непрочитанными в основном аккаунте, запусти агрегатор под отдельным аккаунтом, который имеет доступ к папке и может писать в форум.

## Запуск с нуля

1. Создай приватную супергруппу, включи в ней темы и добавь аккаунт агрегатора. Если агрегатор будет создавать темы, выдай этому аккаунту право «Управление темами».
2. Подготовь [ссылку на общую папку](https://telegram.org/blog/shareable-folders-custom-wallpapers#shareable-chat-folders) и [получи API ID и API hash](https://core.telegram.org/api/obtaining_api_id) для пользовательской сессии.
3. Установи [Docker и Docker Compose](https://docs.docker.com/compose/install/). Склонируй репозиторий и создай локальные файлы. Запускай команды под непривилегированным пользователем с доступом к Docker.

   ```sh
   git clone https://github.com/pachamaker/telegram-aggregator.git
   cd telegram-aggregator
   umask 077
   cp config.example.json config.json
   cp .env.example .env
   mkdir -m 700 state
   id -u
   id -g
   ```

4. Укажи в `.env` значения `AGGREGATOR_UID` и `AGGREGATOR_GID` из вывода. Этот пользователь внутри контейнера должен читать `config.json` и писать в `state/`. Затем собери образ и авторизуй аккаунт.

   ```sh
   docker compose build aggregator
   docker compose run --rm aggregator auth
   docker compose run --rm aggregator forums
   ```

   `auth` сохранит ключи API и сессию в `state/`. Если Telegram спросит код входа и пароль двухэтапной проверки, введи их в терминале. Из вывода `forums` скопируй ID нужного форума в поле `group_id` файла `config.json`.

5. Если будешь настраивать маршруты в терминале, запусти мастер, вставь ссылку на папку и подтверди категории и темы. При запуске с ботом используй режим из следующего раздела.

   ```sh
   docker compose run --rm aggregator init
   docker compose run --rm aggregator check
   docker compose up -d aggregator
   docker compose logs --tail=50 aggregator
   ```

   Для предварительного просмотра приглашения используй `init --preview`. После запуска дождись подходящего нового поста и проверь его тему. В логе появится строка «Публикация» с ID темы и сообщения.

## Управление через Telegram

Создай бота командой `/newbot` у [BotFather](https://t.me/BotFather) и добавь его администратором в целевой форум. Создай отдельную тему «Настройки». Команда ниже покажет её ID и ID администраторов. В `operator_ids` впиши числовой ID человека, который будет управлять ботом. В `admin_topic_id` впиши ID темы. Токен бота задай в локальном `.env` как `AGGREGATOR_BOT_TOKEN`.

```sh
docker compose run --rm aggregator admin-info
docker compose run --rm aggregator init --defer-review
docker compose up -d aggregator
```

В теме «Настройки» отправь `/review@имя_бота` и выбери топики кнопками. Агрегатор начнёт пересылать из канала после назначения темы. `check` нужен после появления хотя бы одного маршрута. Останови сервис перед вызовом `check`, поскольку они используют один каталог состояния.

| Команда | Действие |
|---|---|
| `/settings` | Открыть меню и кнопку «Источники». |
| `/sources` | Показать ссылки на каналы и их топики. Кнопка «Показать ID» выводит идентификаторы для ручных команд. |
| `/review` | Разобрать новые каналы из папки. |
| `/retopic` | Выбрать канал и назначить существующий или создать новый топик. |
| `/route ID ID_ТОПИКА` | Указать топик по числовым ID. |
| `/pause` | Приостановить канал или возобновить пересылку с новых постов. При паузе ожидающие публикации пропускаются. |
| `/reactions` | Выбрать автоматический порог, ввести ручной минимум реакций или выключить фильтр. |
| `/age` | Указать время замера реакций после публикации. |
| `/skips [ID]` | Посмотреть причины последних пропусков. |

Изменения через бот сохраняются в SQLite и применяются во время работы. Для перехода на другой хост перенеси существующий каталог состояния по [инструкции для VPS](docs/deploy-vps.md).

## Как добавить каналы

Добавь каналы в приглашение общей папки и подтверди обновление под аккаунтом агрегатора. Проверь, что источники появились в его папке. Агрегатор сверяет состав папки при запуске и затем примерно раз в сутки. После синхронизации разметь новые каналы через `/review`. Чтобы ускорить сверку, перезапусти сервис. Если работаешь без бота, останови сервис и повтори `init`, чтобы назначить темы новым каналам.

## Как работают фильтры

- Агрегатор проверяет пост или альбом целиком. Отдельный пересказ и тот же файл с другой подписью считаются отдельными публикациями.
- Реакции учитываются там, где Telegram подтверждает их доступность. Автопорог использует медиану по 20–30 сопоставимым публикациям канала. Пока наблюдений меньше 20, пересылка идёт без автопорога. Стартовые сроки замера — 12 часов для «Юмора» и 2 часа для других категорий.
- Сервис начинает читать новые посты с текущей позиции. После каждого прохода ждёт 10 минут. Telegram может увеличить эту паузу при ограничении запросов.

Настройки экземпляра и токены храни локально. `config.example.json` и `.env.example` — шаблоны. `config.json`, `.env` и `state/` содержат настройки и данные конкретного экземпляра.

## Разработка

Для локального запуска или тестирования установи зависимости в виртуальное окружение.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B -m aggregator --help
```

Команды `auth`, `init`, `check` и `run` можно вызвать напрямую через `.venv/bin/python -m aggregator`. При прямом запуске передавай `AGGREGATOR_BOT_TOKEN` через окружение процесса. Docker Compose читает его из `.env`.
