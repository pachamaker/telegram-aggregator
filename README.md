# Telegram Aggregator

Собирает публикации из общей папки Telegram и пересылает их в темы твоей приватной группы. Ты выбираешь, какие каналы читать и в какие темы их направлять. Агрегатор отсекает точные дубли, распознаёт рекламу по явным признакам и умеет отбирать посты по реакциям. Классификация и фильтрация работают локально по правилам.

Один экземпляр обслуживает одну папку и один форум. Пользовательский аккаунт читает источники и пересылает посты. Отдельный бот опционален и нужен для кнопок управления. Если хочешь видеть пересылки непрочитанными в основном аккаунте, запусти агрегатор под отдельным аккаунтом, который имеет доступ к папке и может писать в форум.

## Быстрый старт

Для первой пробы хватит одного аккаунта Telegram, компьютера с Docker и двух активных каналов. Бот нужен для управления кнопками в Telegram. VPS пригодится, если дайджест должен работать, пока компьютер выключен.

1. Создай приватную группу с темами и общую папку с двумя каналами. Получи свои `api_id` и `api_hash` на my.telegram.org. Подробности есть в шагах 1–4 ниже.
2. Склонируй репозиторий, подготовь `.env` и `config.json`, выполни `auth` и запиши ID группы из вывода `forums`. Это шаг 5.
3. Запусти `init`, назначь хотя бы одному каналу тему, затем выполни `check` и запусти контейнер по шагу 6.
4. Дождись нового поста в источнике и найди его в выбранной теме. [Как проверить первую пересылку](#проверка-первой-пересылки)

## Запуск с нуля

### 1. Подготовь аккаунт и компьютер

Понадобятся активный пользовательский аккаунт Telegram, доступ к коду входа и пароль двухэтапной проверки, если она включена. Выбери, под каким аккаунтом будет работать агрегатор, и подготовь его номер для команды `auth`. Второй аккаунт опционален.

На компьютере или VPS установи Git и [Docker с Docker Compose v2](https://docs.docker.com/compose/install/). На Mac запусти Docker Desktop. На Linux выполняй команды под непривилегированным пользователем с доступом к Docker. Если работаешь на VPS из-под root, настрой UID и GID контейнера по [инструкции для VPS](docs/deploy-vps.md#3-восстанови-данные-и-настрой-окружение). Проверь, что доступны Git, Compose и запущенный Docker Engine.

```sh
git --version
docker compose version
docker info --format '{{.ServerVersion}}'
```

**Windows.** Установи WSL 2 с Linux-дистрибутивом, например Ubuntu. В Docker Desktop выбери **Settings → General → Use the WSL 2 based engine** и включи интеграцию для своего Linux-дистрибутива в **Settings → Resources → WSL Integration**. Открой терминал этого дистрибутива, например Ubuntu. Клонируй проект в домашний каталог Linux и выполняй команды README в том же терминале. [Docker Desktop и WSL 2](https://docs.docker.com/desktop/features/wsl/)

### 2. Создай приватную группу с темами

1. В Telegram Desktop открой **☰ → Новая группа**. Добавь аккаунт агрегатора, если он отдельный, и задай название, например «Мой дайджест». На телефоне начни с кнопки нового сообщения. [Создание группы в Telegram](https://telegram.org/faq#q-how-do-i-create-a-group)
2. Открой группу и перейди в **⋯ → Управление группой**. В мобильном приложении нажми название группы и открой редактирование. Проверь, что в поле **Тип группы** выбрано **Частная группа**.
3. В настройках группы включи **Темы** и сохрани изменения. Когда появится список тем, группа готова работать как форум. [Темы в Telegram](https://telegram.org/blog/direct-to-channel-trim-voice-and-more#topic-tabs)
4. Проверь, что аккаунт агрегатора состоит в группе и может отправлять туда сообщения. Если хочешь создавать темы из мастера или бота, выдай **пользовательскому аккаунту агрегатора** право **Управление темами** через список администраторов. Темы можно создавать и вручную.

### 3. Подготовь ссылку на папку с каналами

1. Открой в Telegram **Настройки → Папки чатов → Создать папку**. Дай папке имя, например «Источники дайджеста», и добавь нужные каналы.
2. Открой настройки этой папки и выбери **Поделиться папкой** или **Создать ссылку**. Отметь каналы, которые должен получить аккаунт агрегатора. Для первого запуска можно выбрать два-три канала.
3. Скопируй ссылку вида `https://t.me/addlist/…`. Вставишь её в мастер `init`. Мастер покажет список и попросит подтвердить присоединение под аккаунтом агрегатора.

В приглашение можно добавить публичные каналы и приватные чаты, в которые у тебя есть право приглашать людей. Состав приглашения настраивается отдельно от самой папки. Агрегатор читает только каналы. Группы и личные чаты он пропускает. [Общие папки Telegram](https://telegram.org/blog/shareable-folders-custom-wallpapers#shareable-chat-folders)

### 4. Получи API ID и API hash

Если у тебя уже есть собственная пара `api_id` и `api_hash`, используй её. Ключи относятся к приложению, поэтому с ними можно войти под отдельным аккаунтом агрегатора. [Авторизация в Telethon](https://docs.telethon.dev/en/stable/basic/signing-in.html)

1. Открой [my.telegram.org](https://my.telegram.org/) и войди по номеру своего аккаунта Telegram. Введи код, который пришлёт Telegram.
2. Открой **API development tools** или **Development Tools**. Если приложение уже создано, используй показанные там ключи.
3. Если видишь форму создания приложения, заполни **App title** (например, `My Digest`) и **Short name** (например, `mydigest`). Поле **URL** можно оставить пустым. Для сервера выбери **Bot / Server**, если этот вариант есть в списке платформ. Нажми **Create application**.
4. Скопируй **api_id** (число) и **api_hash** (строку). Их запросит команда `auth`. Токен от BotFather понадобится отдельно и только для меню управления. [Получение ключей Telegram API](https://core.telegram.org/api/obtaining_api_id)

### 5. Установи проект и войди через `auth`

```sh
git clone https://github.com/pachamaker/telegram-aggregator.git
cd telegram-aggregator
umask 077
cp config.example.json config.json
cp .env.example .env
mkdir -m 700 state
chmod 600 config.json .env
id -u
id -g
```

Укажи в `.env` значения `AGGREGATOR_UID` и `AGGREGATOR_GID` из вывода. Например, если обе команды вернули `1000`, укажи `AGGREGATOR_UID=1000` и `AGGREGATOR_GID=1000`. По ним контейнер получит права на чтение `config.json` и запись в `state/`. Оставь `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` пустыми, чтобы `auth` запросил их при запуске.

```sh
docker compose config --quiet
docker compose build aggregator
docker compose run --rm aggregator auth
```

Введи по запросу `api_id`, `api_hash`, номер аккаунта агрегатора в международном формате и код входа. Если Telegram попросит пароль, введи пароль двухэтапной проверки. При успешном входе `auth` сохранит ключи и сессию в `state/`. Храни эти файлы и `.env` локально.

Найди свою группу с темами.

```sh
docker compose run --rm aggregator forums
```

Скопируй число из поля `id` нужной группы в `group_id` файла `config.json`. Используй положительное число из вывода. Если группы нет в списке, проверь, что вошёл под нужным аккаунтом, он состоит в группе и темы включены.

### 6. Настрой маршруты и запусти пересылку

Если хочешь разбирать каналы кнопками, перейди к разделу [Управление через Telegram](#управление-через-telegram). Для настройки в терминале запусти `init`, вставь ссылку на папку и подтверди вступление, категории и темы.

```sh
docker compose run --rm aggregator init &&
  docker compose run --rm aggregator check &&
  docker compose up -d aggregator
docker compose logs --tail=50 aggregator
```

Для предварительного просмотра приглашения выполни `docker compose run --rm aggregator init --preview`.

## Проверка первой пересылки

1. Убедись, что хотя бы одному каналу назначена тема. Если используешь бота, сделай это через `/review`.
2. После запуска дождись строки «Проход завершён» в журнале. При первом чтении канала агрегатор запоминает последний пост и начинает пересылать следующие.
3. Дождись, когда в источнике появится новый пост. После очередного опроса проверь выбранную тему и журнал. Строка «Публикация» содержит ID темы и сообщения. Пауза между опросами составляет 10 минут, а при ограничениях Telegram может быть дольше.

```sh
docker compose ps aggregator
docker compose logs --tail=50 aggregator
```

## Управление через Telegram

Бот опционален. Чтобы настроить управление кнопками, сначала выполни `auth` и заполни `group_id` по шагам выше.

1. Открой [@BotFather](https://t.me/BotFather), отправь `/newbot` и задай отображаемое имя и свободный username на латинице с окончанием `bot`. Сохрани выданный токен в локальном `.env` как `AGGREGATOR_BOT_TOKEN`. [Создание бота и получение токена](https://core.telegram.org/bots/tutorial#obtain-your-bot-token)
2. В целевой группе открой **Управление группой → Администраторы → Добавить администратора** и найди бота по username. Отдельно проверь, что аккаунт, с которого ты будешь отправлять команды, владелец или администратор этой группы.
3. В списке тем нажми **Создать тему** и назови её «Настройки». Узнай ID темы и администратора командой ниже.

```sh
docker compose run --rm aggregator admin-info
```

В `config.json` впиши ID темы «Настройки» в `admin_topic_id`, а числовой ID своего аккаунта из списка администраторов — в массив `operator_ids`.

Пример `config.json` с вымышленными ID. Подставь свои значения из `forums` и `admin-info`.

```json
{
  "group_id": 1000000001,
  "admin_topic_id": 42,
  "operator_ids": [1000000002]
}
```

Затем подготовь очередь разбора и запусти сервис.

```sh
docker compose run --rm aggregator init --defer-review &&
  docker compose up -d aggregator
```

В теме «Настройки» отправь `/review@имя_бота` и выбери топики кнопками. Агрегатор начнёт пересылать из канала после назначения темы. `check` нужен после появления хотя бы одного маршрута. Останови сервис перед вызовом `check`, поскольку они используют один каталог состояния.

| Команда | Действие |
|---|---|
| `/settings` | Открыть меню и кнопку «Источники». |
| `/sources` | Показать ссылки на каналы и их топики. Кнопка «Показать ID» выводит идентификаторы для ручных команд. |
| `/review` | Разобрать новые каналы из папки. |
| `/retopic` | Выбрать канал и назначить существующий или создать новый топик. |
| `/route ID ID_ТОПИКА` | Указать топик по числовым ID. |
| `/pause` | Приостановить канал или возобновить пересылку с новых постов. При паузе ожидающие публикации пропускаются. |
| `/reactions` | Выбрать автоматический порог, ввести ручной минимум реакций или выключить фильтр. |
| `/age` | Указать время замера реакций после публикации. |
| `/skips [ID]` | Посмотреть причины последних пропусков. |

Изменения через бот сохраняются в SQLite и применяются во время работы. Для перехода на другой хост перенеси существующий каталог состояния по [инструкции для VPS](docs/deploy-vps.md).

## Как добавить каналы

Добавь каналы в приглашение общей папки и подтверди обновление под аккаунтом агрегатора. Проверь, что источники появились в его папке. Агрегатор сверяет состав папки при запуске и затем примерно раз в сутки. После синхронизации разметь новые каналы через `/review`. Чтобы ускорить сверку, перезапусти сервис. Если работаешь без бота, останови сервис и повтори `init`, чтобы назначить темы новым каналам.

## Как работают фильтры

- Агрегатор проверяет пост или альбом целиком. Отдельный пересказ и тот же файл с другой подписью считаются отдельными публикациями.
- Реакции учитываются там, где Telegram подтверждает их доступность. Автопорог использует медиану по 20–30 сопоставимым публикациям канала. Пока наблюдений меньше 20, пересылка идёт без автопорога. Стартовые сроки замера — 12 часов для «Юмора» и 2 часа для других категорий.
- Сервис начинает читать новые посты с текущей позиции. После каждого прохода ждёт 10 минут. Telegram может увеличить эту паузу при ограничении запросов.

Настройки экземпляра и токены храни локально. `config.example.json` и `.env.example` — шаблоны. `config.json`, `.env` и `state/` содержат настройки и данные конкретного экземпляра.

## FAQ

**Почему `check` прошёл, а группа пустая?** Команда проверяет доступ к источникам и темам. Для проверки доставки дождись поста, который появился после первого опроса. Если бот уже настроен, команда `/skips` покажет недавние пропуски, например из-за дубля или фильтра реакций. [Проверка первой пересылки](#проверка-первой-пересылки)

**Почему бот не отвечает?** Проверь токен `AGGREGATOR_BOT_TOKEN` и права администратора у бота. Отправь `/settings@имя_бота` в теме «Настройки» от своего имени с аккаунта администратора. Его ID должен быть в `operator_ids`, а ID темы — в `admin_topic_id`. Если поменял `.env` или `config.json`, примени настройки через `docker compose up -d --force-recreate aggregator`.

**Почему не появился добавленный канал?** Проверь состав приглашения `t.me/addlist/…` и наличие канала в папке именно под аккаунтом агрегатора. Затем дождись сверки папки и назначь каналу тему. [Как добавить каналы](#как-добавить-каналы)

**Будет ли дайджест работать после закрытия терминала?** Да, после запуска с `-d` контейнер работает в фоне. Компьютер должен оставаться включённым, а Docker — запущенным. [Перенос на VPS](docs/deploy-vps.md)

## Разработка

Для локального запуска или тестирования установи зависимости в виртуальное окружение.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -B -m unittest discover -s tests -v
.venv/bin/python -B -m aggregator --help
```

Команды `auth`, `init`, `check` и `run` можно вызвать напрямую через `.venv/bin/python -m aggregator`. При прямом запуске передавай `AGGREGATOR_BOT_TOKEN` через окружение процесса. Docker Compose читает его из `.env`.
