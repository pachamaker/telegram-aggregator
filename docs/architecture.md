# Архитектура Telegram Aggregator

Один процесс обслуживает одну общую папку Telegram и один форум. Пользовательская сессия Telethon читает источники и публикует сообщения. Опциональный Bot API обрабатывает команды в выделенной теме. Бот и пересылка используют одну SQLite-базу. Настройки источников, выбранные оператором, применяются в процессе работы.

## Карта кода

| Файл | Ответственность |
|---|---|
| `aggregator/__main__.py` | CLI, авторизация, блокировка каталога состояния, запуск и сверка отправок. |
| `aggregator/setup.py` | Чтение общей папки, первичная классификация, маршрутизация и создание тем с подтверждением. |
| `aggregator/categories.json` | Словарь и пороги классификации. |
| `aggregator/runtime.py` | Обнаружение источников, чтение новых сообщений, очередь, измерение реакций и пересылка. |
| `aggregator/rules.py` | Детерминированные признаки рекламы, реакции и отпечатки публикаций. |
| `aggregator/store.py` | Схема SQLite, начальный импорт настроек и миграция v1. |
| `aggregator/admin.py` | Bot API, проверка полномочий, меню, команды и транзакции настроек. |
| `aggregator/review.py` | Карточки разбора и выбора тем, навигация по каналам и подтверждение правок. |

## Жизненный цикл источника и сообщения

1. `init` связывает папку с форумом. Мастер классифицирует источники по словарю и истории. При `--defer-review` предлагает маршруты в Telegram. Канал без назначенного топика ожидает разбора.
2. Сервис сверяет папку при запуске, затем раз в сутки. При отсутствии источника в папке его курсор и ожидающая очередь сохраняются до возвращения. Для нового источника чтение начинается с текущей позиции.
3. Для каждого источника запись курсора и добавление постов в очередь происходят в одной транзакции. Альбомы группируются перед фильтрацией. Реклама, точные дубли и фильтр реакций проверяются перед отправкой.
4. Перед отправкой запись переходит из `pending` в `sending`. В БД сохраняются топик и идентификаторы запросов. Подтверждённая отправка получает статус `sent` и ID сообщений. Если результат неоднозначен, запись остаётся на сверку. Повтор разрешён после проверки.
5. При смене топика ещё не начатые отправки берут новый маршрут. При паузе ожидающие записи пропускаются, а при возобновлении чтение начинается с новых сообщений. Изменения настроек и ID обновления фиксируются в `admin_changes`.

## Данные экземпляра

| Файл | Содержимое |
|---|---|
| `config.json` | Форум, тема управления, операторы и необязательные начальные параметры. |
| `.env` | Локальное окружение Compose, включая токен бота. |
| `state/aggregator-v2.sqlite3` | Маршруты, настройки, очередь, курсоры, наблюдения, история и состояние карточек. |
| `state/telegram.session` | Авторизованная пользовательская сессия Telethon. |
| `state/credentials.json` | API ID и API hash пользовательской сессии. |

Таблица `sources` хранит рабочую конфигурацию каналов. `config.json` используется для начального импорта и параметров запуска. При переносе действующего экземпляра копируй базу с сессией. `v2.lock` защищает каталог состояния от одновременного доступа двух процессов. Перезапуск на другом хосте требует остановки исходной копии.

## Проверки по зонам

| Изменение | Офлайн-проверка |
|---|---|
| Реклама, дубли или реакции | `tests/test_rules.py` и связанный сценарий в `tests/test_runtime.py`. |
| Курсор, очередь, отправки или миграция | `tests/test_runtime.py`. |
| Вступление в папку, классификация или темы | `tests/test_setup.py`. |
| Полномочия, команды и аудит | `tests/test_admin.py`. |
| Кнопки, формы и сохранение маршрутов | `tests/test_review.py`. |

Тесты имитируют ответы Telegram. Если нужна приёмка в живом форуме, проверяй её отдельно на разрешённом экземпляре. Критерий пересылки — сообщение подтверждено в ожидаемой теме, а состояние очереди содержит его ID.
